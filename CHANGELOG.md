# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow semver once 1.0.0 ships.

## Unreleased

- Specification, milestones and agent workflow (spec-first start of the project).
- Hardening: every performance budget is measured and enforced (a budget nobody measures fails); the app is told of a lone state change at once instead of 100 ms later; fuzz targets and property tests for everything parsed from outside, run nightly; sweeps that prove no secret reaches any output, argument or file outside the secrets files.
- Guide: `docs/adopting-an-existing-vm.md` — putting devbox around a VM that exists, step by step, and going back.
- SSH from anywhere, the host side: `devbox up` routes the SSH host (`--ssh-host`, default `devbox.<domain>`), lets the gateway's own key into the VM from the bridge only, records the VM's SSH host key for the gateway to pin, and lets the owner's keys in once; `devbox down` undoes it. `devbox ssh keys [add|remove]` and `devbox ssh status` manage the paired computers; `devbox connect` prints the one command that sets a computer up; `devbox doctor` checks the route, DNS, the SSH banner through the public host, and both keys in the VM. The gateway image carries the four `devbox-ssh` builds, and tags `ssh-v*` publish them with the setup script, checksums and build attestations.
- SSH from anywhere, the server side: the gateway answers SSH itself on its TCP port and in a WebSocket on the SSH host, lets in only paired keys of the VM user, wakes the VM only for them, shows the wake in the terminal, and relays everything SSH does to the VM over its own pinned connection. `devbox-ssh` is the client that carries SSH in a WebSocket.
- Hub continuous deployment: a push to `main` that changes the hub builds it, attests it and creates a GitHub Deployment; `devbox-hub update` in the VM installs it, checks it, switches to it and goes back if the new hub does not come up, reporting each step to GitHub; the gateway can wake a sleeping VM for it (`deploy.wake_to_deploy`).
- Fixed, found by the first runs on a real Incus VM: waking now asks Incus to restore the saved memory (a start that does not ask throws it away and boots fresh); the VM installer no longer reads its root-only bundle as the user; the hub sets the clock through a helper instead of a sudoers wildcard that newer sudo refuses; `devbox up` remembers the firewall manager and the build it installed.
- Library: `devbox-core`, `devbox-sync` and `devbox-context` 0.1.0, built to be embedded by moi — every host command is a function that returns a report (`setup::{up, down, status, doctor, connect, password}`, rendered by `render::human` / `render::json`), prompts go through `Confirm` and `UpOptions`, all system access through `system::System`, the firewall through `firewall::Manager`; Rust 1.88.
- Setup: `devbox up` plans and applies everything on the host — secrets, the Incus VM (new or adopted), provisioning, dotfiles, host config, Traefik routes, firewall — saving what it replaces, and `devbox down` puts it back. `devbox status`, `doctor`, `connect` and `password` look after a host that is set up.
- Developer context: `devbox context` writes a factual, current description of how you work — environment, languages, git and agent habits, each repository, the last two weeks — into your dotfiles for every agent to read, with secrets redacted, optionally summarized by your own Claude Code, and committed.
- Repo sync: `devbox sync` clones the repositories you own on GitHub and brings every repository in `~/code` up to date — fast-forwarding or rebasing with uncommitted changes carried over, or leaving a repository exactly as it was when anything conflicts.
- Agents app: an installable PWA to watch, answer and start agent sessions from a phone — live session list and terminal screen, one-tap answers, push notifications, wake from sleep, offline shell.
- Agents hub: the app API with sign-in, live state and screen streams, and web push notifications when an agent needs you, finishes a long turn or fails.
- Agents hub core: agent sessions in tmux that survive hub restarts, state from agent hooks through a fast relay, idle reporting to the gateway, repo sync on wake, the `devbox-hub agent` command and hook installers for Claude Code, Codex and opencode.
- Boot screen (sign-in, wake progress with phases and ETA, repo sync, errors), embedded in the gateway; gateway container image and Compose file; `devbox-gateway healthcheck`.
- Gateway core: wake with phases and learned ETAs, restore-to-cold fallback, idle sleep, HTTP/WebSocket/SSH proxying, wake authentication, health and status endpoints, unconfigured mode and config hot reload.
- Contracts: JSON Schemas for every message and config file with generated Go, Rust and TypeScript types; config parsing that reports every problem at once; argon2id password hashes shared by Go and Rust.
- Repository scaffold: the `devbox-gateway`, `devbox-hub` and `devbox` binaries with every command present but not implemented, the web workspace, CI, and the hygiene and budget checks.
